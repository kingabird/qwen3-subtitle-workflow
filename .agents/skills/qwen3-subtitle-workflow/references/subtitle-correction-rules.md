# 音频优先字幕校对规则

本规则适用于 `video-subtitle transcribe` 之后、`video-subtitle align` 之前的正稿校对。校对确认后的完整正文必须保存为 `proofread.txt`；不得只存在于会话上下文中。

## 职责边界

Agent 负责语义和专名校对、生成 `proofread-report.md` 和 `proofread.txt`，并从正稿派生对齐全文和自然字幕短句。判断依据包括音频、可用原稿和用户提供的校对信息。

`video-subtitle` 提供本地执行流程。`transcribe` 调用 MLX Qwen ASR，生成初稿和带约 20 秒分段的 `<初稿文件名去掉扩展名>-timed.json`；`align` 只执行 Qwen 强制对齐、基于静音的时间调整和校验。它不会在 Python 中擅自改写语义、修正专名或决定断句。

例如 `asr-draft.txt` 对应 `asr-draft-timed.json`。定位 JSON 提供约 20 秒分段的近似时间，用于回听和选择长音频切点。最终字幕时间由 `video-subtitle align` 生成，再根据音频复核和调整。

## 文字来源优先级

1. 实际口播是最终依据。
2. 原稿用于校正专名、术语、年代、作品名和语义。
3. ASR 仅是音频内容的初稿，不可直接覆盖原稿。
4. 仅在确认存在口播改写、增删或词序变化时，保留实际口播版本；不能仅凭一次 ASR 结果推翻原稿。
5. 原稿有明显错别字时，可按通行写法修正；每处修正记录到差异单，保留原文和修改理由。

## 原稿中的编辑标记

Markdown 标题、注释、舞台说明、链接、署名和删除线文字先作为编辑信息检查。只要音频确实念出了其中的文字，就按实际口播保留。正文也需要核对是否实际说出。

## 标点

`proofread.txt` 是唯一的校对确认正稿，保留最少但必要的 `，。？！；`，供 Agent 判断语义和自然断句。专名可保留 `《》`、`·`、英文连字符、撇号和 `R. Mutt`。`proofread-report.md` 用于记录修改依据和未解决问题，不是完整正稿，不能作为自然断句的输入。

生成断句后，`transcript.txt`、`cues.txt` 和最终 SRT 的字幕正文不保留中文标点或全角符号，包括 `，。？！；：、《》〈〉“”‘’（）【】`、顿号、省略号、破折号和全角 `％`。仅保留下列有语义的内部符号：

- 姓名内部的间隔号 `·`，例如 `玛丽·居里`；
- 英文词内的连字符或撇号 `-`、`'`、`’`，例如 `ready-made`、`don't`；
- 两个数字之间的 `.`、`/`、`:`、`-`，例如 `3.5`、`1/1`、`12:30`、`2026-07`；
- 数字后的 ASCII `%`，例如 `20%`、`3.5%`；不得使用全角 `％`；
- 上述符号只在示例所示的内部位置放行；孤立、重复、行首或行尾的其他符号仍视为非法；本条仅约束 `transcript.txt`、`cues.txt` 和最终 SRT，不约束校对正稿；
- 不保留多余空格和 Markdown 符号；
- `proofread-report.md` 是说明文档，可正常使用标点，不受字幕正文限制；
- `transcript.txt` 必须从 `proofread.txt` 派生，是完整连续、去除中文标点并保留上述白名单符号的口播文本，只供 Qwen Forced Aligner 对齐；
- `cues.txt` 必须通过分析 `proofread.txt` 的语义和必要标点自然断出，一行一条，供 token 匹配和 SRT 显示；
- 去除空白后，`transcript.txt` 必须与拼接后的 `cues.txt` 完全一致；白名单符号也参与精确匹配，不得在两者之间改写或删除。

## 数字

- 年份、年代、日期一律用阿拉伯数字，例如 `1917 年`、`1950 年代`、`20 世纪`；
- 10 及以上的一般数字用阿拉伯数字，例如 `12 个`；
- 1–9 的普通叙述数量用中文数字，例如 `六美元`、`几个`；
- 小数、百分比、比例、时间、日期和版本可保留通行的 ASCII 写法，例如 `3.5`、`20%`、`1/1`、`12:30`、`2026-07`、`1.0版`；
- 同一处数字在 `transcript.txt` 和 `cues.txt` 中必须采用完全相同的写法，不得一边写 `20%`、另一边写 `百分之20`；
- 编号和尺寸优先采用清晰且与实际口播对应的写法；
- 固定引语或明确的口播读法优先于上述格式规则。

## 交付门槛

将经审校的完整文字写入 `proofread.txt` 后，再派生对齐文件并运行 `video-subtitle align`。有原稿时，Agent 的审校可完成此确认。只有音频时，依据用户对校对结果的确认或已给出的审校授权继续。若正稿与音频不一致，先核对并修正正稿。时间轴应对应实际口播位置。

## 自动校对、确认与继续

有原稿时，默认流程自动生成校对报告，并继续生成正稿、断句和 SRT；报告是审计记录，不是等待用户确认的闸门。只有专名或语义冲突无法依据音频和原稿判断、文本大段缺失／倒序，或 Forced Aligner 校验失败时才停止并请求人工处理。

只有音频时，先以音频和 ASR 初稿进行一轮审校。用 `asr-draft-timed.json` 为有疑问的语义、同音误识、漏字和专有名词标明时间位置。保留 `asr-draft.txt`、`asr-draft-timed.json` 与 `proofread-report.md`。按用户确认或已给出的审校授权写入 `proofread.txt`，再派生 `transcript.txt` 和 `cues.txt`。

默认保留初稿及过程文件。用户要求清理初稿时，可用 `--delete-asr-draft asr-draft.txt` 在对齐校验成功后删除。保留 `asr-draft-timed.json`、校对报告、正稿、对齐全文、分句、token JSON、验证报告和最终 SRT，以支持复查。
